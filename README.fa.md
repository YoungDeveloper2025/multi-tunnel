# Multi Tunnel

مدیریت تانل Backhaul، Rathole و GOST با منوی ترمینالی برای Ubuntu 22.04 یا جدیدتر، معماری amd64 و آدرس IPv4.
نسخهٔ **2.5.1** پس از انتخاب نقش خارج، دو حالت **خودکار** و **دستی** دارد. حالت خودکار با پنج تنظیم اصلی و اطلاعات ورود SSH هر دو سمت را می‌سازد. حالت دستی، پرسش‌های کامل تنظیمات و انتخاب بین راه‌اندازی ایران با SSH یا انتقال دستی کد اتصال را حفظ می‌کند. بعد از گزینهٔ `1` برای ساخت تانل، **اولین سؤال** همچنان نقش سرور فعلی است. برای انتقال دستی کد، دسترسی مدیریتی بین دو سرور لازم نیست.
انتخاب‌های منو عددی‌اند: عدد گزینه را وارد کنید یا برای حفظ مقدار پیش‌فرض نمایش‌داده‌شده Enter بزنید. پاسخ بله در سؤال‌های معمولی `1` و خیر `2` است. در حالت خودکار، دانلود بسته‌های Ubuntu از مسیر خارج و حذف و ساخت مجدد تانل هم‌نام با `y/n` و پیش‌فرض `y` پرسیده می‌شوند. در مسیر دستی، تأیید راه‌اندازی ایران، مسیر دانلود بسته‌ها و جایگزینی تانل هم‌نام پیش‌فرض ندارند. پاسخ نامعتبر دوباره پرسیده می‌شود؛ Enter فقط در سؤال دارای پیش‌فرض پذیرفته می‌شود. در حالت دستی، تأیید حجم دانلود بسته‌های Ubuntu با `y/n` و پیش‌فرض `y` است؛ حالت خودکار حجم را نمایش می‌دهد و همین تأیید پیش‌فرض را خودکار اعمال می‌کند. سؤال‌ها با خط خالی از متن اطراف جدا می‌شوند. نام تانل، آدرس‌ها، مسیر فایل‌ها، پورت‌ها و کد اتصال در سؤال‌های مربوط همچنان به‌صورت متن وارد می‌شوند.

## قراردادن پروژه در GitHub

فایل‌های این پوشه، از جمله `multi-tunnel.py`، `install.sh` و `README.md`، را در ریشهٔ مخزن خود قرار دهید. دستور آمادهٔ زیر برای نام پیشنهادی **`YoungDeveloper2025/multi-tunnel`** و شاخهٔ **`main`** نوشته شده است. مخزن باید ابتدا با همین نام ساخته و فایل‌ها در آن بارگذاری شوند؛ این پروژه به‌جای شما در GitHub منتشر نشده است. اگر نام دیگری انتخاب کردید، نام مخزن را در نشانی دانلود و مقدار `--repo` تغییر دهید.
دستور نصب از GitHub، فایل `multi-tunnel.py` را از ریشهٔ همان مخزن دریافت می‌کند. اگر شاخهٔ شما `main` نیست، هم نام شاخه در نشانی دانلود و هم مقدار `--ref` را تغییر دهید.

## روش اول: اجرای مستقیم فایل روی سرور

فایل `multi-tunnel.py` را روی سرور قرار دهید و در پوشهٔ آن اجرا کنید:

```bash
sudo python3 multi-tunnel.py
```

این روش برای اجرای اولیه به مخزن GitHub نیاز ندارد. نصب بسته‌های موردنیاز و دریافت باینری موتورهای تانل همچنان به اینترنت نیاز دارد. اگر روش دستی را انتخاب می‌کنید، همین فایل را روی سرور دوم نیز اجرا کنید. روش SSH فایل را خودکار به ایران منتقل می‌کند.

## روش دوم: نصب از فایل‌های محلی

پس از دریافت فایل‌های مخزن، در همان پوشه اجرا کنید:

```bash
sudo bash install.sh --local .
sudo multi-tunnel
```

می‌توانید مسیر فایل را نیز صریح وارد کنید:

```bash
sudo bash install.sh --local /root/multi-tunnel.py
```

در این حالت نصاب سورس برنامه را دانلود نمی‌کند. اگر بسته‌های ضروری نصب نباشند، آن‌ها را از مخازن Ubuntu نصب می‌کند.

## روش سوم: نصب از GitHub

برای روش خودکار، فقط روی خارج اجرا کنید؛ برای روش دستی، روی هر دو سرور:

```bash
curl -fsSL --retry 3 https://raw.githubusercontent.com/YoungDeveloper2025/multi-tunnel/main/install.sh -o /tmp/multi-install.sh
sudo bash /tmp/multi-install.sh --repo YoungDeveloper2025/multi-tunnel --ref main
sudo multi-tunnel
```

اگر `curl` نصب نیست، ابتدا اجرا کنید:

```bash
sudo apt-get update
sudo apt-get install -y curl ca-certificates
```

نصاب منو را خودکار باز نمی‌کند؛ دستور `sudo multi-tunnel` آن را باز می‌کند. برای نصب یک نسخهٔ مشخص می‌توانید نام tag یا شناسهٔ commit را به `--ref` بدهید. برای بررسی SHA256 سورس نیز گزینهٔ اختیاری `--sha256 HASH` وجود دارد. مقدار `HASH` باید SHA256 واقعی فایل `multi-tunnel.py` همان نسخه باشد.

## ساخت اولین تانل

اسکریپت را روی خارج اجرا کنید، `1) Create tunnel` و سپس `2) Foreign` را انتخاب کنید. نقش پیش‌فرض نیز `2` است. در سؤال بعد، یکی از دو حالت ساخت را با عدد انتخاب کنید:

| شماره | حالت | کاربرد |
|---|---|---|
| `1`، پیش‌فرض | `Automatic` | ساخت هر دو سمت با پنج تنظیم اصلی، اطلاعات SSH و سایر مقادیر پیش‌فرض |
| `2` | `Manual` | تعیین نام، نوع انتقال، پورت‌ها و تنظیمات تکمیلی و سپس انتخاب روش راه‌اندازی ایران |

### ساخت خودکار هر دو سمت

پس از انتخاب `Automatic`، پنج تنظیم اصلی دقیقاً به ترتیب زیر پرسیده می‌شوند:

| ترتیب | تنظیم | پیش‌فرض و رفتار |
|---|---|---|
| `1` | IP یا دامنهٔ خارج | IP عمومی شناسایی‌شدهٔ همین سرور؛ با Enter پذیرفته می‌شود |
| `2` | IPv4 سرور ایران | ندارد؛ باید وارد شود |
| `3` | موتور تانل | `1` Backhaul، `2` Rathole، `3` GOST؛ پیش‌فرض `1` |
| `4` | نوع انتقال | فهرست عددی همان موتور؛ پیش‌فرض `1` یعنی TCP، به‌جز GOST با Cloudflare که `3` یعنی WS است |
| `5` | دانلود بسته‌های Ubuntu با اینترنت خارج داخل SSH | فقط `y` یا `n` کوچک؛ پیش‌فرض `y` و قابل‌پذیرش با Enter |

اگر در تنظیم اول IP وارد کنید، سؤال Cloudflare حذف و مقدار آن خودکار خیر می‌شود. اگر دامنه وارد کنید، سؤال تکمیلی دربارهٔ روشن‌بودن پروکسی نارنجی می‌آید؛ پاسخ معمول عددی `1` بله و `2` خیر است. برای دامنه فقط نامی مانند `tunnel.example.com` وارد کنید، بدون `https://`، مسیر یا شمارهٔ پورت. در سرور دارای NAT یا چند IP، مطمئن شوید IP پیشنهادی، ورودی اتصال را به همین سرور می‌رساند. اگر IP عمومی شناسایی نشود باید آن را وارد کنید.
بعد از این پنج تنظیم، **پورت SSH ایران با پیش‌فرض `22` و رمز مخفی حساب root** پرسیده می‌شوند. برنامه تنظیمات ورود SSH ایران را تغییر نمی‌دهد؛ ورود root با رمز و، در صورت انتخاب دانلود از خارج، انتقال پورت SSH باید از قبل مجاز باشند. Enter در هر سؤال دارای پیش‌فرض، همان مقدار را انتخاب می‌کند؛ IP ایران و رمز پیش‌فرض ندارند.
نام اولیهٔ تانل، نگاشت پورت‌ها و گزینه‌های پیشرفته از پیش‌فرض‌ها انتخاب می‌شوند. اتصال SSH و پیش‌نیازهای ایران پیش از ساخت سمت خارج بررسی می‌شوند؛ پس از آن هر دو سمت ساخته و آزمون زندهٔ اتصال از ایران اجرا می‌شود. توقف یا خطا پیش از ساخت خارج به‌عنوان موفقیت ساخت گزارش نمی‌شود.

#### مقادیر خودکار

- نام اولیه `mytunnel` است. اگر روی خارج وجود داشته باشد، برای همان سرور سؤال حذف و ساخت مجدد با پیش‌فرض `y` می‌آید. اگر نام نهایی خارج روی ایران هم وجود داشته باشد، برای ایران نیز همین سؤال پرسیده می‌شود. Enter یا `y` جایگزین می‌کند؛ `n` تانل قبلی را حفظ و نام آزاد مانند `mytunnel-2` انتخاب می‌کند. ورودی نامعتبر دوباره پرسیده می‌شود. پاسخ هر سرور فقط مربوط به همان سرور است.
- نوع انتقال انتخاب شما حفظ می‌شود؛ پیش‌فرض هر موتور TCP است. فقط برای GOST با Cloudflare، پیش‌فرض WS می‌شود و توضیح کوتاه مربوط به آن نمایش داده می‌شود. در Backhaul و Rathole، انتقال داخلی انتخاب‌شده از انتقال کمکی GOST WSS عبور می‌کند؛ انتخاب TCP با Cloudflare فعال، اتصال بیرونی را به TCP ساده تبدیل نمی‌کند.
- پورت‌های ورودی اولیه ایران و مقصد خارج `443,2083,2053,1115,1117` هستند. پورت اشغال‌شدهٔ ورودی ایران به پورت آزاد تغییر می‌کند؛ ترتیب مقصدها و پورت سرویس خارج تغییر نمی‌کند. **نگاشت نهایی ایران به خارج را پس از نصب بخوانید** و برای کانفیگ کاربران از پورت نهایی ایران استفاده کنید.
- در حالت نیازمند گیرندهٔ خارج، پورت ارتباط `8443` است؛ اگر آزاد نباشد، پورت آزاد دیگری انتخاب می‌شود. در Cloudflare، جایگزین‌های خودکار به `2087` و `2096` محدود هستند؛ برنامه پورت اشغال‌شده را با توقف سرویس دیگر آزاد نمی‌کند.
- keepalive و تنظیمات کنترل، multiplexing و sniffer مطابق پیش‌فرض‌های همان موتور اعمال می‌شوند؛ تغییر سفارشی آن‌ها از حالت دستی یا ویرایش ممکن است.
- سؤال مسیر دانلود بسته‌ها با `y/n` و پیش‌فرض `y` است. تأیید حجم دانلود در ساخت خودکار دوباره پرسیده نمی‌شود: حجم نمایش داده می‌شود و پیش‌فرض `y` خودکار اعمال می‌شود.

جایگزینی، پیکربندی و سرویس‌های تانل جدید را از ابتدا ایجاد می‌کند. فایل‌ها و سرویس‌های مدیریتی قبلی پس از موفقیت پاک می‌شوند؛ تا پایان عملیات محلی، نسخهٔ قبلی برای بازیابی در صورت شکست نگه داشته می‌شود. این پشتیبان، تانل فعال دیگری کنار تانل جدید نیست. بسته‌های مشترک سیستم یا باینری موتورهایی که تانل‌های دیگر نیز استفاده می‌کنند حذف نمی‌شوند. بازیابی مربوط به همان عملیات روی همان سرور است: اگر ساخت خارج موفق شود ولی مرحلهٔ ایران شکست بخورد، خارج برای تکرار راه‌اندازی حفظ می‌شود و خودکار به نسخهٔ قبلی برنمی‌گردد.

#### انتخاب غیر از WS برای GOST پشت Cloudflare

همهٔ انتقال‌های GOST در فهرست قابل انتخاب‌اند، اما در این پیاده‌سازی عبور GOST از پروکسی نارنجی فقط با WS انجام می‌شود. اگر با Cloudflare روشن، TCP، UDP، gRPC یا TCPMux را انتخاب کنید، برنامه می‌پرسد آیا به‌جای عبور از Cloudflare، مستقیم به IPv4 واقعی خارج متصل شود. پیش‌فرض این تأیید `n` است.
فقط با تأیید صریح `y`، آدرس دامنه با IP واقعی خارج جایگزین و حالت Cloudflare برای این تانل خاموش می‌شود؛ نوع انتقال انتخاب‌شده حفظ می‌شود. IP عمومی شناسایی‌شدهٔ همین خارج استفاده می‌شود و اگر شناسایی نشده باشد، IP واقعی را می‌پرسد. با پاسخ `n` یا Enter، به انتخاب نوع انتقال برمی‌گردید تا بتوانید WS را انتخاب کنید. اتصال مستقیم بدون اطلاع و تأیید شما جایگزین مسیر Cloudflare نمی‌شود.

#### گواهی در ساخت خودکار Cloudflare

ابتدا گواهی و کلید خصوصی مسیر استاندارد زیر روی **خارج** بررسی می‌شوند؛ `DOMAIN` همان دامنهٔ واردشده است:

```text
/etc/letsencrypt/live/DOMAIN/fullchain.pem
/etc/letsencrypt/live/DOMAIN/privkey.pem
```

اگر گواهی معتبر و پوشش دامنه و تطابق کلید درست باشد، همان فایل‌ها استفاده می‌شوند. در غیر این صورت، Certbot برای همان دامنه بدون سؤال دوباره دربارهٔ دامنه یا مسیر فایل اجرا می‌شود و پس از موفقیت، گواهی بررسی و استفاده می‌شود. این حالت برای پیدا کردن گواهی در مسیر سفارشی جست‌وجو نمی‌کند؛ برای معرفی Cloudflare Origin CA یا فایل‌های دلخواه، حالت دستی را انتخاب کنید.
صدور واقعی به DNS، دسترسی شبکه و ACME وابسته است و با انتخاب حالت خودکار تضمین نمی‌شود. پورت TCP `80` باید آزاد و قابل‌دسترسی باشد؛ سرویس دیگری خودکار متوقف نمی‌شود. اگر Cloudflare روشن است، درخواست `/.well-known/acme-challenge/` باید بدون مانع به خارج برسد. SSL کلودفلر باید `Full (strict)` باشد. جزئیات صدور و تمدید در بخش گواهی آمده است.

### ساخت دستی روی خارج

1. پس از نقش خارج، `2) Manual` را انتخاب کنید.
2. نام تانل را وارد کنید؛ مقدار پیش‌فرض `mytunnel` است. موتور را با `1` Backhaul، `2` Rathole یا `3` GOST انتخاب کنید؛ پیش‌فرض `1` است. نوع انتقال نیز عددی و پیش‌فرض اولیهٔ TCP گزینهٔ `1` است.
3. در سؤال `enter your foriegn domain or ip`، IP عمومی خارج یا دامنهٔ آن را وارد کنید. پیش‌فرض ساخت جدید، IP شناسایی‌شدهٔ همین سرور است؛ در ویرایش آدرس قبلی حفظ می‌شود. اگر IP وارد کنید، سؤال Cloudflare حذف می‌شود؛ برای دامنه این سؤال نمایش داده می‌شود.
4. پورت‌ها و تنظیمات تکمیلی را تعیین کنید. در حالت Cloudflare، مسیر گواهی و کلید خصوصی روی همین سرور خارج را معرفی کنید.
5. سرویس‌های خارج راه‌اندازی می‌شوند و کد `MULTI2.` روی یک خط مستقل با فاصله از متن بالا و پایین نمایش داده می‌شود. سمت خارج آماده است و منتظر اتصال ایران می‌ماند.
6. سؤال «راه‌اندازی ایران از همین خارج» فقط `y` یا `n` بدون پیش‌فرض می‌پذیرد. با `n`، کد را خودتان روی ایران وارد کنید. با `y`، راه‌اندازی SSH زیر انجام می‌شود.

### راه‌اندازی ایران با SSH پس از ساخت دستی

ابتدا سؤال زیر می‌آید:

```text
Download Ubuntu packages through this Foreign server over SSH? (y/n)
```

پیش‌فرض ندارد و فقط حروف کوچک `y` یا `n` را می‌پذیرد. با `y` بسته‌های Ubuntu با اینترنت خارج دریافت می‌شوند؛ با `n` دانلود مستقیم از ایران انجام می‌شود و اصل راه‌اندازی SSH ادامه دارد. سپس IP ایران، پورت SSH با پیش‌فرض `22` و رمز مخفی root پرسیده می‌شوند.
اگر نام تانل روی ایران موجود باشد، تأیید `y/n` بدون پیش‌فرض می‌آید:

- با `y`، تانل جدید در همان نام محلی جایگزین می‌شود؛ اگر راه‌اندازی یا آزمون اتصال شکست بخورد، نسخهٔ قبلی بازیابی می‌شود.
- با `n`، تانل قبلی حفظ و نام محلی آزاد مانند `mytunnel-2` انتخاب می‌شود؛ شناسهٔ ارتباط با خارج تغییر نمی‌کند.
- پورت ورودی اشغال‌شدهٔ ایران به پورت آزاد تغییر می‌کند و نگاشت نهایی نمایش داده می‌شود. پورت مقصد خارج تغییر نمی‌کند.

گزینهٔ `9) Set up Iran via SSH` در مدیریت تانل خارج نیز همین جریان پرسش‌های دستی را با کد فعلی تکرار می‌کند؛ لازم نیست سمت خارج را دوباره بسازید. شکست راه‌اندازی ایران، تانل ساخته‌شدهٔ خارج را حذف نمی‌کند.

### امنیت SSH و انتقال فایل‌ها

ایران باید Ubuntu 22.04+، معماری amd64 و ورود root با رمز از SSH داشته باشد. برنامه تنظیمات SSH را تغییر نمی‌دهد و کلید ورود SSH به ایران ارسال نمی‌کند. رمز هنگام ورود مخفی است و در فایل تنظیمات، فایل اتصال یا خط فرمان ذخیره نمی‌شود. در اولین اتصال کلید میزبان ثبت می‌شود؛ تغییر کلید ثبت‌شده اتصال را متوقف می‌کند. ابزارهای `openssh-client` و `sshpass` هنگام نیاز روی خارج نصب می‌شوند.
فایل مدیر و موتورهای لازم با بررسی SHA256 از خارج به ایران منتقل می‌شوند. کد اتصال داخل نشست SSH ارسال و بدون بازکردن منوی تعاملی ایران استفاده می‌شود. سرویس‌های ایران و فایروال تنظیم می‌شوند و نتیجهٔ آزمون زنده در ترمینال خارج نمایش داده می‌شود. پس از پایان، نشست SSH بسته می‌شود؛ systemd اجرای تانل را ادامه می‌دهد.

### مسیر دانلود و حجم بسته‌ها

با انتخاب دانلود از خارج، درخواست‌های HTTP/HTTPS و حل نام مخازن APT از مسیر موقت SOCKS داخل همان اتصال SSH به خارج می‌رسند. این مسیر فقط روی loopback ایران قابل‌دسترسی است، به انتقال پورت SSH نیاز دارد و پس از کار بسته می‌شود؛ پراکسی دائمی نوشته نمی‌شود. خارج باید به منابع دانلود دسترسی داشته باشد؛ ایران برای این نصب به دسترسی مستقیم مخازن Ubuntu یا GitHub نیاز ندارد.
در حالت دانلود مستقیم، ایران باید مخازن Ubuntu را باز کند. در هر دو حالت، انتخاب نسخه و وابستگی‌ها را APT روی **خود ایران** انجام می‌دهد؛ بسته‌های سیستم‌عامل خارج به‌جای بسته‌های مناسب ایران کپی نمی‌شوند. این نسخه آرشیو آفلاین `.deb` تولید نمی‌کند.
شش پیش‌نیاز اصلی `python3`، `openssl`، `ufw`، `iproute2`، `ca-certificates` و `iptables` هستند. اگر همه نصب باشند، APT برای آن‌ها اجرا نمی‌شود و حجم دانلود بسته‌هایشان صفر است؛ فایل مدیر و باینری‌های لازم تانل همچنان بررسی و منتقل می‌شوند.
اگر پیش‌نیازی موجود نباشد، ابتدا فهرست مخازن ایران به‌روزرسانی می‌شود. این دریافت برای محاسبهٔ حجم لازم است و **پیش از اعلام و تأیید حجم بسته‌ها** انجام می‌شود. سپس حجم فایل‌های پیش‌نیازهای نصب‌نشده و وابستگی‌هایشان نمایش داده می‌شود؛ فایل‌های قابل‌استفادهٔ کش APT از دانلود کنار گذاشته می‌شوند. اندازهٔ نمایش‌داده‌شده شامل فهرست مخازن، مدیر یا موتورهای تانل نیست و اندازهٔ نصب‌شده روی دیسک نیز محسوب نمی‌شود.
در **حالت دستی** و دانلود از خارج، تأیید حجم با `y/n` و پیش‌فرض `y` پرسیده می‌شود: Enter ادامه می‌دهد و `n` راه‌اندازی ایران را لغو می‌کند، درحالی‌که تانل ساخته‌شدهٔ خارج حفظ می‌شود. در **حالت خودکار** حجم همچنان نمایش داده می‌شود اما پیش‌فرض `y` خودکار اعمال می‌شود. پیش‌نیازهای نصب‌شده دوباره هدف نصب نیستند؛ وابستگی لازم ممکن است با تصمیم APT به‌روزرسانی شود.

### روی سرور ایران، در روش دستی

1. همان نسخهٔ اسکریپت را اجرا کنید و گزینهٔ `1` را بزنید.
2. در اولین سؤال نقش، عدد `1` یعنی `iran` را انتخاب کنید.
3. کل کد `MULTI2.` تولیدشده روی خارج را در سؤال `Connection code` وارد کنید. اگر کد طولانی است، آن را دستی در یک فایل روی ایران ذخیره کنید و به‌جای متن کد، مسیری مانند `@/root/connection.txt` وارد کنید؛ میان `@` و مسیر فاصله نگذارید. نام، دامنه، نوع انتقال و پورت‌ها از همین کد خوانده می‌شوند؛ دوباره پرسیده نمی‌شوند. Enter بدون کد، عملیات را لغو می‌کند.
4. فقط برای Backhaul، دربارهٔ فعال‌کردن sniffer محلی سؤال می‌شود. روی ایران هیچ مسیری برای گواهی یا کلید خصوصی پرسیده نمی‌شود.
5. پس از راه‌اندازی هر دو سمت، از منوی مدیریت روی **ایران** گزینهٔ `2` با متن `test tunnel connection` را اجرا کنید.

کد اتصال و فایل متنی حاوی آن شامل اطلاعات احراز هویت تانل‌اند؛ آن‌ها را در مخزن عمومی، اسکرین‌شات یا گزارش عمومی قرار ندهید. فایل واردشده با `@` باید فقط همان کد اتصال باشد، نه فایل گواهی یا کلید خصوصی. برای ساخت این اتصال، کلید خصوصی سرور خارج به ایران منتقل نمی‌شود.
تا زمانی که سمت دوم تنظیم نشده باشد، برقرارنبودن ارتباط بین دو سرور طبیعی است. سرویس‌ها پس از بستن ترمینال و راه‌اندازی مجدد سیستم توسط systemd اجرا می‌شوند.

## پورت‌ها و نگاشت مقصد

با زدن Enter در سؤال پورت‌ها، این پورت‌های ورودی روی ایران انتخاب می‌شوند:

```text
443,2083,2053,1115,1117
```

ورودی سفارشی را با کاما جدا کنید. برای مقصد متفاوت از قالب `IRAN:FOREIGN` استفاده کنید:

```text
443:9443,2083:2083,1115:1115
```

در این مثال، اتصال کاربر به پورت `443` ایران به سرویس مقصد روی پورت `9443` خارج منتقل می‌شود. سرویس مقصد، مانند Xray، باید از قبل روی پورت مقصد فعال باشد.
پورت پیش‌فرض ارتباط بین دو سرور `8443` است و با پورت‌های ورودی کاربران تفاوت دارد. در حالت‌های دارای گیرندهٔ تانل روی خارج، این پورت نباید با پورت سرویس مقصد روی همان سرور تداخل داشته باشد. GOST سادهٔ TCP و UDP مستقیماً به پورت‌های مقصد متصل می‌شوند.
قوانین موردنیاز با UFW روی هر سرور اضافه می‌شوند. پس از ساخت، فهرست پورت‌های ورودی لازم برای فایروال ارائه‌دهنده نیز نمایش داده می‌شود. در GOST سادهٔ TCP/UDP، یک پورت تصادفی روی خارج برای پاسخ به آزمون احرازهویت‌شده اضافه می‌شود؛ برای کارکرد آزمون، آن پورت نیز باید در فایروال ارائه‌دهنده باز باشد. اسکریپت UFW را خودکار فعال یا reset نمی‌کند. اگر فایروال پنل ارائه‌دهندهٔ VPS دارید، پورت‌های لازم را در آن نیز باز کنید.

## نوع‌های انتقال

| موتور | گزینه‌ها | کاربرد در این پروژه |
|---|---|---|
| Backhaul | `tcp`، `udp`، `ws`، `wsmux`، `tcpmux` | تانل معکوس با تنظیم خودکار سرویس محلی هر سمت |
| Rathole | `tcp`، `ws` | تانل معکوس با تنظیم خودکار سرویس محلی هر سمت |
| GOST | `tcp`، `udp` | ارسال مستقیم از ایران به IP یا دامنه و پورت مقصد خارج |
| GOST | `ws`، `grpc`، `tcpmux` | ارسال از ایران به گیرندهٔ GOST روی خارج؛ ارتباط دارای TLS است |

Backhaul تنظیمات keepalive، multiplexing، sniffer و نگاشت پورت را نیز ارائه می‌کند. در حالت TCP امکان فعال‌کردن UDP-over-TCP وجود دارد.
برای اینکه آدرس ارتباط همچنان IP یا دامنهٔ **خارج** باشد، اتصال Backhaul و Rathole در این پروژه از یک انتقال کمکی GOST استفاده می‌کند. در اتصال مستقیم این انتقال TLS است و در حالت Cloudflare، WSS. به همین دلیل UDP مربوط به Backhaul نیز در مسیر بین دو سرور از یک جریان قابل‌اعتماد عبور می‌کند و ویژگی تأخیر UDP مستقیم را ندارد. گزینه‌های TCP/WS خود Backhaul یا Rathole، نوع انتقال داخل این ارتباط را تعیین می‌کنند. بنابراین انتخاب TCP برای Backhaul یا Rathole با Cloudflare فعال، عبور از Cloudflare را غیرفعال نمی‌کند؛ اتصال بیرونی همچنان WSS است. تغییر نوع انتقال از ویرایش خارج، کد جدید `MULTI2.` می‌سازد و باید روی ایران هم اعمال شود.

## استفاده از Cloudflare

1. رکورد ساب‌دامنه را روی IP عمومی سرور خارج قرار دهید و پروکسی نارنجی را روشن کنید.
2. SSL/TLS را روی `Full (strict)` قرار دهید و WebSockets را فعال نگه دارید.
3. گواهی عمومی معتبر یا Cloudflare Origin CA باید همان ساب‌دامنه را پوشش دهد و روی سرور خارج موجود باشد.
4. در سؤال دامنه، فقط نامی مانند `tunnel.example.com` وارد کنید؛ بدون `https://`، مسیر یا شماره پورت.
5. سؤال مربوط به Cloudflare را با عدد `1` یعنی بله پاسخ دهید.
6. در حالت دستی، مسیر گواهی و کلید خصوصی را روی **خارج** وارد کنید؛ در حالت خودکار فایل معتبر مسیر استاندارد استفاده یا برای همان دامنه گواهی درخواست می‌شود. نمونهٔ مسیر:

```text
/etc/letsencrypt/live/tunnel.example.com/fullchain.pem
/etc/letsencrypt/live/tunnel.example.com/privkey.pem
```

این مسیرها نمونه هستند و باید با مسیر واقعی فایل‌های شما جایگزین شوند. گواهی و کلید خصوصی فقط روی خارج استفاده می‌شوند؛ کپی‌کردن کلید خصوصی روی ایران لازم نیست.
پورت `8443` برای اتصال WSS پیش‌فرض است. پورت‌های HTTPS پشتیبانی‌شده در این ابزار برای Cloudflare عبارت‌اند از `443,2053,2083,2087,2096,8443`. پورت‌های ورودی کاربران روی ایران، از جمله `1115` و `1117`، لازم نیست جزو پورت‌های Cloudflare باشند؛ ترافیک آن‌ها داخل اتصال WSS روی پورت منتخب حمل می‌شود.
در GOST، حالت Cloudflare با گزینهٔ `ws` کار می‌کند. در Backhaul و Rathole، انتقال کمکی WSS امکان عبور ارتباط از Cloudflare را فراهم می‌کند. قواعد چالش تعاملی یا احراز هویت مرورگری روی مسیر WebSocket تانل می‌توانند مانع اتصال شوند.
گیرندهٔ GOST فایل‌های گواهی را مستقیماً از همین مسیرهای سرور خارج می‌خواند. پس از تمدید گواهی، سرویس تانل خارج را از منوی مدیریت restart کنید تا گواهی جدید بارگذاری شود. این گزینه ابتدا اعتبار گواهی، نام دامنه و تطابق کلید را دوباره بررسی می‌کند. اگر مسیر فایل‌ها عوض شده است، تنظیمات تانل را نیز ویرایش کنید.
برای hook تمدید گواهی می‌توانید سرویس GOST همان تانل را restart کنید؛ در دستور زیر `NAME` را با نام واقعی تانل جایگزین کنید:

```bash
systemctl restart multi-NAME-gost.service
```

این دستور مستقیم، اعتبارسنجی اضافی منوی مدیریت را اجرا نمی‌کند. در حالت مستقیمِ بدون Cloudflare، برای حالت‌های دارای TLS گواهی اختصاصی با اعتبار ۸۲۵ روز خودکار روی خارج ساخته می‌شود و فقط گواهی عمومی آن در کد اتصال ایران قرار می‌گیرد. برای نوسازی آن، تانل خارج را ویرایش و کد جدید را روی ایران وارد کنید. حالت‌های GOST سادهٔ TCP و UDP گواهی ندارند.

## مدیریت، ویرایش، حذف و آزمون

منوی اصلی شامل `1` ساخت، `2` مدیریت تانل‌های محلی، `3` بازیابی عملیات محلی قطع‌شده، `4` دریافت گواهی ساب‌دامنه، `5` نصب پنل `mhsanaei/3x-ui`، `6` نصب پنل `alireza0/x-ui` و `0` خروج است. فهرست تانل‌ها ابتدا بر اساس موتور به ترتیب Backhaul، Rathole و GOST، و در هر گروه بر اساس نام مرتب می‌شود. در مدیریت، ابتدا شمارهٔ تانل را انتخاب می‌کنید و سپس شمارهٔ عملیات را وارد می‌کنید؛ پیش‌فرض عملیات `1` یعنی وضعیت است:

| شماره | متن گزینه | عملکرد |
|---|---|---|
| `1` | `Status` | وضعیت سرویس‌ها و زمان آخرین آزمون ثبت‌شده |
| `2` | `test tunnel connection` | روی ایران: آزمون زندهٔ سرتاسری؛ روی خارج: وضعیت و راهنمای اجرای آزمون از ایران |
| `3` | `Edit` | روی خارج: تغییر تنظیمات و تولید کد جدید؛ روی ایران: دریافت کد جدید همان تانل |
| `4` | `Delete` | حذف سمت محلی پس از تأیید عددی؛ Enter پیش‌فرض خیر را انتخاب می‌کند |
| `5` | `Restart` | راه‌اندازی مجدد سرویس‌های سمت محلی |
| `6` | `Logs` | نمایش لاگ سرویس‌های محلی |
| `7` روی خارج | `Show connection code` | نمایش دوبارهٔ کد اتصال محرمانه |
| `8` روی خارج، `7` روی ایران | `get cert for sub domain` | گرفتن گواهی برای ساب‌دامنه روی سرور فعلی |
| `9` روی خارج | `Set up Iran via SSH` | نصب و ساخت سمت ایران یا تکرار راه‌اندازی با کد اتصال فعلی خارج |
| `10` روی خارج، `8` روی ایران | نصب آخرین نسخه پنل mhsanaei/3x-ui | اجرای نصاب رسمی روی همین سرور |
| `11` روی خارج، `9` روی ایران | نصب آخرین نسخه پنل alireza0/x-ui | اجرای نصاب رسمی روی همین سرور |

عملیات معمول مدیریت روی سرور فعلی انجام می‌شوند؛ گزینهٔ راه‌اندازی SSH، سمت ایران را از خارج تنظیم می‌کند. حذف تانل در ایران آن را از خارج حذف نمی‌کند؛ حذف را روی هر دو سرور انجام دهید.
**هر ویرایش روی خارج، حتی با حفظ مقادیر قبلی، اطلاعات احراز هویت و شناسهٔ نسخهٔ اتصال را عوض می‌کند.** در حالت مستقیم دارای TLS، گواهی اختصاصی نیز دوباره ساخته می‌شود. بعد از ویرایش خارج حتماً در ایران همان تانل را انتخاب کنید، گزینهٔ `3` یعنی `edit` را بزنید و کد جدید خارج را وارد کنید. تا هماهنگ‌شدن دو سمت، اتصال قطع می‌ماند. برای تانل‌های دارای نام محلی متفاوت در ایران، شناسهٔ اصلی اتصال خارج حفظ می‌شود؛ در ویرایش باید کد مربوط به همان اتصال خارج را وارد کنید.
آزمون اتصال، انتقال داده از مسیر تانل را با پیام تصادفی و احراز هویت بررسی می‌کند. موفقیت آن به معنی صحت تنظیمات Xray یا سلامت سرویس مقصد کاربران نیست. مشاهدهٔ `active` برای سرویس systemd نیز به‌تنهایی اتصال واقعی بین دو سرور را ثابت نمی‌کند.
در آزمون ایران، پیام `Tunnel connection successful.` به معنی موفقیت و پیام `Tunnel connection unsuccessful.` همراه دلیل خطا به معنی شکست آزمون است. روی خارج، برنامه برای انجام آزمون زنده شما را به ایران راهنمایی می‌کند و صرفاً از روی وضعیت سرویس‌ها موفقیت اتصال را اعلام نمی‌کند.

## گرفتن گواهی ساب‌دامنه

در سروری که گواهی لازم است، گزینهٔ `4` منوی اصلی با متن `get cert for sub domain` را انتخاب کنید. همین گزینه در منوی مدیریت هر تانل هم وجود دارد؛ روی خارج دامنهٔ ذخیره‌شدهٔ تانل، اگر دامنه باشد، به‌عنوان پیشنهاد استفاده می‌شود. روی ایران باید دامنهٔ مربوط به همین سرور را وارد کنید. برای تانل Cloudflare این کار را روی **سرور خارج** انجام دهید. این گزینه حتی قبل از ساخت اولین تانل از منوی اصلی در دسترس است.

ساب‌دامنه را بدون `https://`، شمارهٔ پورت یا مسیر وارد کنید. ابتدا Certbot نصب می‌شود و سپس درخواست گواهی برای همان ساب‌دامنه ارسال می‌شود؛ نمونه:

```bash
apt-get install certbot -y
certbot certonly --standalone --agree-tos --register-unsafely-without-email -d tunnel.example.com --cert-name tunnel.example.com
```

اعتبارسنجی HTTP باید به همین سرور برسد. پورت ورودی TCP `80` باید در فایروال سرور و ارائه‌دهنده باز باشد و برنامهٔ دیگری نباید آن را اشغال کرده باشد. برنامه سرویس‌های موجود را خودکار متوقف نمی‌کند. قانون لازم `80/tcp` در UFW در صورت نیاز اضافه می‌شود و برای تمدیدهای بعدی باقی می‌ماند؛ تنظیم فایروال ارائه‌دهنده با شماست. در Cloudflare، خاموش‌کردن موقت پروکسی نارنجی برای صدور اولیه ساده‌ترین حالت است؛ در صورت روشن‌بودن آن، مسیر `/.well-known/acme-challenge/` باید بدون چالش مرورگر یا ریدایرکت ناسازگار به همین سرور برسد. وجود رکورد AAAA ناسازگار نیز می‌تواند باعث شکست اعتبارسنجی شود.

پس از موفقیت، مسیر گواهی و کلید خصوصی نمایش داده می‌شود؛ برای نمونه:

```text
/etc/letsencrypt/live/tunnel.example.com/fullchain.pem
/etc/letsencrypt/live/tunnel.example.com/privkey.pem
```

گزینهٔ `--cert-name` با نام همان ساب‌دامنه برای ثابت‌ماندن مسیرها اضافه می‌شود؛ وجود و اعتبار فایل‌ها قبل از اعلام موفقیت بررسی می‌شود. گزینهٔ مستقل گرفتن گواهی، تنظیمات تانل موجود را خودکار تغییر نمی‌دهد؛ مسیرهای نمایش‌داده‌شده را هنگام ساخت دستی یا ویرایش خارج وارد کنید. ساخت خودکار، گواهی مسیر استاندارد همان دامنه را بررسی و استفاده می‌کند. صدور واقعی به DNS، دسترسی شبکه و پاسخ سرویس صدور گواهی بستگی دارد؛ آزمون‌های خودکار این پروژه گواهی واقعی درخواست نمی‌کنند.

## نصب آخرین نسخهٔ پنل

از منوی اصلی یا مدیریت تانل، یکی از گزینه‌های زیر را انتخاب کنید:

| گزینهٔ اصلی | متن |
|---|---|
| `5` | Install the latest mhsanaei/3x-ui panel |
| `6` | Install the latest alireza0/x-ui panel |

برنامه قبل از اجرا، نصب روی سرور فعلی را توضیح می‌دهد. اگر از قبل پنل x-ui موجود باشد، تأیید عددی با پیش‌فرض خیر می‌گیرد. برای نصب روی **سرور خارج**، گزینه را در منوی اجراشده روی خارج انتخاب کنید. نصب پنل به ایران ارسال نمی‌شود و به‌طور خودکار بخشی از ساخت تانل نیست.
نصاب از نشانی رسمی زیر با HTTPS دریافت و سپس با Bash، **بدون آرگومان شمارهٔ نسخه** اجرا می‌شود؛ خود نصاب آخرین انتشار پایدار پروژه‌اش را انتخاب می‌کند:

- [نصاب رسمی mhsanaei/3x-ui](https://raw.githubusercontent.com/mhsanaei/3x-ui/master/install.sh)
- [نصاب رسمی alireza0/x-ui](https://raw.githubusercontent.com/alireza0/x-ui/master/install.sh)

پرسش‌ها و خروجی نصاب رسمی مستقیماً در همان ترمینال نمایش داده می‌شوند. نصب این پنل‌ها تنظیمات VLESS یا کاربران شما را خودکار نمی‌سازد؛ آن‌ها را در پنل تنظیم کنید و پورت مقصد تانل را به پورت سرویس مناسب وصل کنید.
هر دو پروژه از `x-ui.service` و مسیرهای مشترک `x-ui` استفاده می‌کنند؛ روی یک سرور، یکی را انتخاب کنید. نصب پروژهٔ دیگر روی پنل موجود می‌تواند فایل‌ها و سرویس موجود را تغییر دهد و نباید آن را نصب دو پنل مستقل فرض کرد. مسیر موقت APT مربوط به راه‌اندازی ایران برای این نصاب‌ها فعال نیست؛ سروری که پنل روی آن نصب می‌شود باید منابع دانلود موردنیاز نصاب را باز کند.

## نمایش پیشرفت و Ctrl+C

دانلود فایل مدیر، نصاب پنل و باینری‌های تانل، و ارسال فایل‌ها به ایران با نمایش پیشرفت همراه است. برای فایل با اندازهٔ معلوم، حجم منتقل‌شده و درصد نمایش داده می‌شود. در عملیات چندمرحله‌ای مثل به‌روزرسانی فهرست مخازن، دانلود بسته‌ها و نصب آن‌ها، پیشرفت همان مرحله نمایش داده می‌شود؛ اتمام دانلود به معنی اتمام نصب یا موفقیت تست تانل نیست.
حالت خودکار نیز همین پیشرفت انتقال فایل، دانلود و نصب بسته‌ها را به همراه وضعیت مرحلهٔ جاری نمایش می‌دهد؛ درصد یک فایل، درصد کلی ساخت دو سمت نیست. اگر اندازهٔ کل معلوم نباشد، نمایش فعالیت جای درصد حدسی را می‌گیرد. برای ارسال فایل، نتیجهٔ موفقیت تنها پس از پایان انتقال و بررسی فایل اعلام می‌شود. خروجی نصاب‌های رسمی پنل مستقیماً نمایش داده می‌شود و میزان جزئیات نوار پیشرفت آن‌ها به ابزارهای همان نصاب بستگی دارد.
با فشردن **Ctrl+C در خود منوی اصلی، انتخاب تانل، منوی مدیریت یا انتخاب بازیابی**، برنامه کاملاً بسته می‌شود و منو تکرار نمی‌شود. هنگام پاسخ‌دادن به تنظیمات یا اجرای یک عملیات، **Ctrl+C همان عملیات را لغو می‌کند** و پس از پاک‌سازی به منو بازمی‌گردید. نشست SSH و مسیر موقت دانلود بسته می‌شوند و اطلاعات محرمانه در فایل دائمی نوشته نمی‌شوند. لغو عملیات، دانلود یا نصب نیمه‌تمام را موفق گزارش نمی‌کند.
لغو همهٔ تغییرات سیستم را به عقب برنمی‌گرداند: بسته‌هایی که APT پیش‌تر نصب کرده و تغییراتی که نصاب پنل پیش‌تر انجام داده است ممکن است باقی بمانند. اگر نصب APT قطع شود، ممکن است نیاز به بررسی وضعیت بسته‌ها یا اجرای مجدد نصب باشد. تعویض تنظیمات تانل از سازوکار پشتیبان‌گیری و بازیابی خودش استفاده می‌کند؛ اگر اجرای برنامه یا ارتباط در لحظهٔ نامناسب قطع شود، وضعیت سمت ایران را بررسی و در صورت نیاز گزینهٔ بازیابی یا راه‌اندازی SSH را دوباره اجرا کنید.

## فایل‌ها و نسخهٔ قبلی

فایل اجرایی نصب‌شده در `/usr/local/lib/multi-tunnel/multi-tunnel.py` و فرمان آن در `/usr/local/bin/multi-tunnel` قرار می‌گیرند. تنظیمات هر تانل زیر `/etc/multi-tunnel` ذخیره می‌شوند.

### به‌روزرسانی از نسخه‌های 2.0 تا 2.5.0 به 2.5.1

فایل جدید `multi-tunnel.py` را جای فایل قبلی قرار دهید و اجرا کنید:

```bash
sudo python3 multi-tunnel.py
```

اگر از نصاب استفاده می‌کنید، فایل‌های جدید را در یک پوشه قرار دهید و از همان پوشه اجرا کنید:

```bash
sudo bash install.sh --local .
sudo multi-tunnel
```

در روش دستی، این کار را روی هر سرور جداگانه انجام دهید؛ راه‌اندازی SSH نسخهٔ مدیر را به ایران منتقل می‌کند. تنظیمات موجود با `schema_version: 2` و کدهای اتصال `MULTI2.` سازگار می‌مانند. برای به‌روزرسانی خود برنامه لازم نیست تانل‌های سالم را حذف، دوباره ایجاد یا ویرایش کنید. ویرایش تنظیمات تانل خارج همچنان مطابق بخش مدیریت، کد اتصال جدید تولید می‌کند.

محدودیت مهاجرت زیر فقط مربوط به **نسخهٔ v1 که با SSH هر دو سرور را مدیریت می‌کرد** است و شامل نسخه‌های 2.0، 2.1، 2.2، 2.3 و 2.4 نمی‌شود: اگر تنظیمات v1 موجود باشند، نصب نسخهٔ جدید متوقف می‌شود تا با اسکریپت قبلی تانل‌های قدیمی را حذف یا مهاجرت کنید. فایل نصب‌شده و تنظیمات v1 خودکار جایگزین نمی‌شوند.

## محدودهٔ بررسی

اعتبارسنجی‌های انجام‌شده و سناریوهای آزمایشی در این پروژه جای آزمایش روی دو VPS واقعی ایران و خارج را نمی‌گیرند. مسیر واقعی Cloudflare و کیفیت ارتباط در شبکهٔ شما باید پس از نصب آزمایش شوند. این پروژه تضمینی دربارهٔ دسترسی شبکه یا کیفیت ارتباط در همهٔ ارائه‌دهندگان ارائه نمی‌کند.

## آزمون‌های مخزن

بررسی نحوی نصاب و آزمون‌های خودکار با Python استاندارد اجرا می‌شوند:

```bash
bash -n install.sh
python3 -m unittest discover -s tests -v
```

آزمون انتقال واقعی با باینری‌های رسمی، در محیط محلی و بدون تغییر systemd یا UFW، نیز قابل اجرا است:

```bash
python3 tests/integration.py --gost /path/to/gost --backhaul /path/to/backhaul --rathole /path/to/rathole
```

مسیرها باید فایل اجرایی نسخه‌های پین‌شدهٔ پروژه باشند. این آزمون از پوشه‌های موقت، گواهی آزمایشی و پورت‌های آزاد محلی استفاده می‌کند. اگر تمام پورت‌های HTTPS مجاز برای سناریوی WSS اشغال باشند، باید محیط آزمایشی مناسب فراهم شود.
گردش‌کار GitHub Actions آزمون‌های Python استاندارد و بررسی نحو را اجرا می‌کند؛ آزمون یکپارچهٔ بالا جداگانه اجرا می‌شود. این گردش‌کار به حساب Cloudflare یا سرور خارجی متصل نمی‌شود و نصب سرویس سیستمی یا آزمون واقعی WAN انجام نمی‌دهد. باینری موتورهای تانل جزو فایل‌های مخزن نیستند؛ برنامه هنگام نیاز نسخه‌های مشخص را از انتشارهای رسمی دریافت و SHA256 آرشیو و فایل اجرایی را بررسی می‌کند.

## مجوز و منابع

کد مدیر تانل و نصاب این پروژه با مجوز MIT منتشر می‌شوند. [Smite](https://github.com/zZedix/Smite) الهام‌بخش قابلیت‌ها بوده است؛ سورس آن در این پروژه کپی نشده است. این پروژه مستقل است و وابستگی سازمانی به Smite یا سازندگان موتورهای تانل ندارد.
باینری‌های GOST، Backhaul و Rathole مجوزهای مستقل خود را دارند. اطلاعات و پیوند سورس نسخه‌های مورد استفاده در [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) آمده است.

## قفل نصب بسته‌های اوبونتو

اگر `unattended-upgr` قفل `/var/lib/dpkg/lock-frontend` را گرفته باشد، نصب به‌روزرسانی اوبونتو در حال انجام است. پیام `SSH tool installation failed` مربوط به نصب ابزارهای SSH روی **سرور خارج** و قبل از اتصال به ایران است.

نسخهٔ 2.5.1 برای نصب بسته‌های محلی، با قابلیت خود APT تا **۳۰۰ ثانیه** منتظر قفل dpkg می‌ماند و زمان اجرای نصب نیز جداگانه در نظر گرفته شده است. فایل قفل حذف نمی‌شود و به‌روزرسانی خودکار متوقف نمی‌شود. قفل فهرست مخازن در `apt-get update` جداست؛ اگر آن قفل اشغال بود، پس از پایان عملیات دیگر دوباره تلاش کنید.

برای رفع خطای نصب ابزارهای SSH، روی خارج اجرا کنید:

```bash
sudo apt-get -o DPkg::Lock::Timeout=300 install -y openssh-client sshpass
sudo multi-tunnel
```

سپس مدیریت تانل‌ها، تانل خارج و گزینهٔ `9) Set up Iran via SSH` را انتخاب کنید. نیازی به ساخت مجدد تانل خارج نیست. اگر پس از پایان مهلت هنوز قفل در اختیار به‌روزرسانی بود، صبر کنید تا تمام شود و دوباره تلاش کنید؛ فایل‌های قفل dpkg را حذف نکنید.
